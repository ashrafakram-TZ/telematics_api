Deploying Your Own Cloud MQTT Server vs. HiveMQ

A complete operational and strategic guide explaining why self-hosting your own Eclipse Mosquitto broker on a cloud VPS (AWS, DigitalOcean, GCP) is vastly superior to HiveMQ Cloud, followed by a production-ready step-by-step deployment guide with full cloud topology diagrams and terminal commands.

1 What is the Use of Making Our Own Server Rather Than HiveMQ?

When you register on HiveMQ Cloud (as shown in your screenshot under license "Jolly Mason"), you are given an evaluation license capped at 25 concurrent connections and 25 messages/second. Building your own self-hosted Mosquitto server solves 5 critical commercial and technical bottlenecks:

ADVANTAGE 1 1. Eliminates the 25 Device Paywall

HiveMQ charges aggressively once you exceed 25 devices. A commercial fleet of 200 vehicles can cost $200 - $400/month on managed cloud brokers. On your own VPS, Mosquitto costs a flat $4 - $5 / month total for 500 or even 10,000 vehicles.

ADVANTAGE 2 2. 100% Data Sovereignty & Privacy

Vehicle telemetry contains sensitive data: live coordinates, driver identities, routes, speed violations, and cargo details. With your own server, data never passes through a 3rd party broker where it could be logged or intercepted.

ADVANTAGE 3 3. Sub-Millisecond Colocation Latency (<0.5ms)

With HiveMQ Cloud, messages travel over the public internet to HiveMQ's servers, then travel back over the internet to your NestJS backend (~80-150ms). When you host your own Mosquitto container on the same cloud server as your backend and PostgreSQL database, packets travel over an internal virtual bridge in less than 0.5ms!

ADVANTAGE 4 4. Complete Control Over Persistence & Auth

You can configure local disk volume persistence, set up automated database authentication, generate custom token-based ACLs, and retain historical data indefinitely without artificial retention limits.

3 Complete Step-by-Step Server Setup Guide

Follow these exact terminal commands on your clean Ubuntu 22.04 / 24.04 cloud instance:

Step 1: Harden Ubuntu Security & Open MQTT Ports

# 1. Update operating system packages
sudo apt update && sudo apt upgrade -y

# 2. Allow SSH remote administration
sudo ufw allow 22/tcp

# 3. Allow Hardware GPS Trackers to connect over raw TCP
sudo ufw allow 1883/tcp

# 4. Allow Browser Web Map to connect over WebSockets
sudo ufw allow 9001/tcp

# 5. Allow standard Web & SSL traffic
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# 6. Enable the firewall
sudo ufw enable

Step 2: Install Docker Engine & Compose Suite

# Automated Docker installation script
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# Allow your user to run Docker commands without sudo
sudo usermod -aG docker $USER
sudo apt install docker-compose-plugin -y

Step 3: Create Mosquitto Configuration & Encrypted Passwords

# 1. Create project directories
mkdir -p ~/telematics-cloud/mosquitto/config ~/telematics-cloud/mosquitto/data ~/telematics-cloud/mosquitto/log

# 2. Create the production mosquitto.conf
cat << 'EOF' > ~/telematics-cloud/mosquitto/config/mosquitto.conf
persistence true
persistence_location /mosquitto/data/
log_dest file /mosquitto/log/mosquitto.log
log_type error
log_type warning
log_type notice
log_type information

# Hardware Tracker Listener (Raw TCP)
listener 1883 0.0.0.0
protocol mqtt

# Web Browser Live Map Listener (WebSockets)
listener 9001 0.0.0.0
protocol websockets

# Security & Authentication
allow_anonymous false
password_file /mosquitto/config/password.txt
EOF

# 3. Generate encrypted password hash file
touch ~/telematics-cloud/mosquitto/config/password.txt
docker run --rm -v ~/telematics-cloud/mosquitto/config:/mosquitto/config eclipse-mosquitto:2.0 mosquitto_passwd -b /mosquitto/config/password.txt telematics_admin StrongSecretPass2026!

Step 4: Create Cloud Docker Compose Deployment File

cat << 'EOF' > ~/telematics-cloud/docker-compose.yml
version: '3.8'

services:
  mosquitto:
    image: eclipse-mosquitto:2.0
    container_name: telematics-mosquitto
    restart: always
    ports:
      - "1883:1883"
      - "9001:9001"
    volumes:
      - ./mosquitto/config/mosquitto.conf:/mosquitto/config/mosquitto.conf:ro
      - ./mosquitto/config/password.txt:/mosquitto/config/password.txt:ro
      - ./mosquitto/data:/mosquitto/data
      - ./mosquitto/log:/mosquitto/log
    networks:
      - telematics-net

  postgres:
    image: postgres:16-alpine
    container_name: telematics-postgres
    restart: always
    environment:
      POSTGRES_USER: telematics_user
      POSTGRES_PASSWORD: SecretDbPassword2026!
      POSTGRES_DB: telematics_db
    volumes:
      - pgdata:/var/lib/postgresql/data
    networks:
      - telematics-net

networks:
  telematics-net:
    driver: bridge

volumes:
  pgdata:
EOF

# Start the cloud broker in detached background mode
cd ~/telematics-cloud && docker compose up -d

Step 5: Verify Your Live Broker

# 1. Verify that containers are running and healthy
docker compose ps

# 2. Live stream all incoming vehicle telemetry
docker exec -it telematics-mosquitto mosquitto_sub -t "telematics/#" -u telematics_admin -P "StrongSecretPass2026!" -v
Step 6: Point Physical Vehicle Trackers to Your Server

Configure your 4G GPS tracker (Coban, Teltonika, Concox, Sinotrack) by sending an SMS to the vehicle's SIM card:
SERVER,1,54.120.x.x,1883,0#
The vehicle will immediately establish a persistent TCP session with your Mosquitto container on port 1883. Telemetry packets will stream every 5 seconds, persist into PostgreSQL, and move vehicle pins smoothly on your web dashboard!
